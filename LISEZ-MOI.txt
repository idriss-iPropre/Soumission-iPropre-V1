CORRECTION LIENS + CLIPBOARD - 20 mai 2026
============================================

DEUX PROBLÈMES CORRIGÉS :

────────────────────────────────────────────
PROBLÈME 1 — Liens ?mode=client&s=rLkWW (page blanche)
────────────────────────────────────────────

Cause :
  Les liens au format ?s=rLkWW sont générés par l'ancien système
  qui appelle Google Sheets pour résoudre l'ID. Ce système ne
  fonctionne plus de manière fiable.

Solution :
  Le fichier envoi.jsx joint utilise UNIQUEMENT is.gd / v.gd /
  tinyurl pour raccourcir les URLs. Les NOUVEAUX liens seront du
  format :

      https://is.gd/abc123          (idéal, ~22 caractères)
      https://v.gd/abc123           (secours)
      https://tinyurl.com/AaBbCcDd  (URLs longues > 4800 car.)

  Si vous voyez encore "?mode=client&s=XXX" après déploiement,
  c'est que le fichier n'est PAS encore en ligne (cache GitHub
  Pages ou push manquant).

────────────────────────────────────────────
PROBLÈME 2 — Il faut cliquer plusieurs fois pour copier
────────────────────────────────────────────

Cause :
  Le navigateur bloque navigator.clipboard.writeText() après un
  "await" parce que le geste utilisateur est perdu. Du coup :
    1er clic → silencieux ou prompt non visible
    2e clic → idem
    3e clic → parfois ça marche

Solution :
  Méthode de copie synchrone (textarea + execCommand) qui
  fonctionne TOUJOURS, même après une attente asynchrone.

────────────────────────────────────────────
COMMENT VÉRIFIER QUE LE FICHIER EST BIEN DÉPLOYÉ
────────────────────────────────────────────

1. Ouvrez l'app dans Chrome
2. Cmd+Option+J (Mac) ou F12 (Windows) → onglet "Console"
3. Cliquez sur "Formulaire" ou "Lecture seule"
4. Vous devez voir dans la console :

   [iPropre] createShortLink v2 (is.gd/tinyurl) — long URL length: ...
   [iPropre] createShortLink result: https://is.gd/...

   Si vous voyez l'ancien message ou rien → le fichier n'est PAS
   déployé. Forcer le rafraîchissement avec Cmd+Shift+R.
