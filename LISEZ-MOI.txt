1. RACCOURCISSEUR : DA.GD AJOUTÉ EN PREMIER
═══════════════════════════════════════════════════════════

Diagnostic depuis votre console :
  [iPropre] Shortener (server-side tinyurl): https://tinyurl.com/...

Apps Script a réussi à appeler tinyurl mais is.gd et v.gd ont
échoué. Cause probable : is.gd rate-limite les IP Google
(Apps Script tourne sur des IPs partagées).

Solution : ajout de da.gd EN PREMIER dans la liste des services.
da.gd est un raccourcisseur fiable, sans page de prévisualisation
ni publicités, et n'a pas de problème avec les IP Google.

Ordre essayé par Apps Script :
  1. da.gd      → https://da.gd/abc        (idéal — pas d'ad)
  2. is.gd      → https://is.gd/abc        (si da.gd indisponible)
  3. v.gd       → https://v.gd/abc
  4. spoo.me    → https://spoo.me/abc
  5. tinyurl    → dernier recours (page preview avec pubs)

Logs Apps Script améliorés : chaque échec est enregistré avec
sa raison (HTTP 4xx, réponse invalide, etc.). Pour les voir :
  Apps Script → Exécutions → cliquer une exécution → Journaux.

2. CLIPBOARD : COPIE QUI MARCHE DU PREMIER COUP
═══════════════════════════════════════════════════════════

Problème :
  Après un `await`, le navigateur perd le "user gesture token",
  donc `document.execCommand('copy')` ET `navigator.clipboard`
  échouent. Le code tombait sur `window.prompt()` qui était
  supprimé parce que le PDF s'ouvrait dans un autre onglet.

Solution moderne :
  Utilisation de `navigator.clipboard.write([new ClipboardItem({
    'text/plain': promise
  })])` — l'appel CLIPBOARD est synchrone (préserve le geste),
  et la promesse est résolue PLUS TARD avec le lien généré.

  Chrome / Safari / Edge supportent ce pattern. C'est la méthode
  recommandée officielle pour copier un résultat asynchrone.

Résultat :
  Un seul clic suffit pour copier "Formulaire" ou "Lecture seule".
  Le toast "Lien copié : https://..." s'affiche dès que la
  génération aboutit.

   6. Cmd+Shift+R dans le navigateur
